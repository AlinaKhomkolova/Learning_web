# Django-приложение с деплоем на сервер

## Описание

Этот проект представляет собой Django-приложение, которое контейнеризовано с использованием Docker и Docker Compose.
Также настроен процесс CI/CD с использованием GitHub Actions для автоматического деплоя на удаленный сервер.

## Требования

Перед настройкой и деплоем на сервер убедитесь, что у вас установлены следующие инструменты:

- **Docker** и **Docker Compose** на сервере
- **Git** для клонирования репозитория
- Доступ к удаленному серверу для деплоя

## Шаги по настройке удаленного сервера и деплоя приложения

### 1. Клонирование репозитория

Клонируйте репозиторий на удаленный сервер, чтобы начать настройку:

```bash
git clone git@github.com:AlinaKhomkolova/Learning_web.git
cd your-Learning_web
```

### 2. Установка Docker:

Установка Docker:
Обновите систему:

```bazaar
sudo apt-get update
```

Установите необходимые зависимости:

```
sudo apt-get install apt-transport-https ca-certificates curl software-properties-common
```

Добавьте Docker-репозиторий:

```bazaar
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
```

### 3. Установка Docker Compose:

Загрузите последнюю версию Docker Compose:

```bazaar
pip iinstall docker-compose
```

### 4. Запуск контейнеров

После того как сервер настроен, используйте Docker Compose для создания и запуска контейнеров

```bazaar
sudo docker-compose up --build -d
```

### 5. Настройка CI/CD с GitHub Actions

В проекте настроен процесс CI/CD с использованием GitHub Actions. Этот процесс автоматически запускается при каждом пуше
в репозиторий, чтобы собрать образ Docker и развернуть приложение на сервере.

Процесс CI/CD:

1. Каждый пуш в основную ветку инициирует сборку Docker-образа.
2. После успешной сборки образа происходит деплой на сервер через SSH.

Этот workflow включает в себя:

1. Скачивание исходного кода из репозитория.
2. Сборку Docker-образа.
3. Публикацию образа на Docker Hub.
4. Подключение через SSH к серверу и выполнение команд для обновления контейнеров.

Теперь ваше приложение готово к автоматическому деплою. Каждый раз, когда изменения будут пушиться в основную ветку,
приложение будет автоматически обновляться на сервере.
